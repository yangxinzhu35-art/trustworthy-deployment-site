Why this matters

A false negative may miss a customer who leaves. A false positive may consume outreach budget. The threshold makes this trade-off explicit and reviewable.

Cost-sensitive metrics

Accuracy counts every error equally. Churn decisions have unequal business consequences, so the deployment monitors metrics connected to the retention decision.

Recall / reduce missed churn

Recall = TP / (TP + FN). It measures how many actual churn customers are identified.

False-negative rate / risk

FNR = FN / (TP + FN). It measures the churn customers the workflow misses.

Precision / outreach efficiency

Precision = TP / (TP + FP). It measures how useful the prioritised list is.

Outreach workload

The number of customers sent to review must fit the retention team's weekly capacity.

Failure response runbook

1. Pause business use of the output. 2. Inspect logs and input validation results. 3. Quarantine the failed file. 4. Fix data or deployment configuration. 5. Rerun the batch and record the new run.

Responsible deployment

The model supports human decision-making. It does not automatically penalise, cancel or exclude customers.

Model owner

Owns model version, evaluation metrics, retraining and rollback decisions.

Data owner

Owns schema, missing values, data quality and privacy checks.

Retention team

Reviews the prioritised list and decides whether outreach is appropriate.

Cloud owner

Monitors Lambda, S3, EventBridge, permissions and CloudWatch alerts.
